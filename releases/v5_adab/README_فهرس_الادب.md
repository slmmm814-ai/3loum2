# محرك بحث "فهرس الأدب" (part1) — نفس منهجية v2

## المصدر
`فهرس_الادب_part1_sqlite3` (رفعه المستخدم، 1GB بعد فك الضغط): 136 كتاب، تصنيفات
"الأدب" و"النحو والصرف"، 102,506 صفحة مصدرية (FTS5 trigram).

## ما بُني هنا
| الخطوة | النتيجة |
|---|---|
| تفكيك الصفحات إلى فقرات/جمل (`01_build_passages_adab.py`) | **358,934 فقرة** (بدل 102,506 صفحة خام) — نفس منطق تقسيم v3 حرفياً |
| BM25 سطحي + جذري (`07b_build_bm25_and_stems_adab.py`) | 673,313 كلمة فريدة موحَّدة إلى **65,495 جذراً** عبر ISRI stemmer |
| محرك بحث هجين (`08_hybrid_search_adab.py`) | نفس منهجية v2: BM25 سطحي + BM25 جذري + fuzzy بمسافة تحرير حقيقية + توسّع صرفي، مدموجة عبر RRF |

## فرق مهم عن نسخة البلاغة (v2): لا توجد طبقة FastText/LSA هنا
هذه المدونة أكبر 5 أضعاف (358,934 فقرة مقابل 73,199)، وتدريب FastText من الصفر
على هذا الحجم داخل حاوية بذاكرة 3.9GB يحتاج بناءً منفصلاً وأطول من الوقت
المتاح لهذه الجلسة. البحث هنا يعتمد فقط على القنوات النصية/الصرفية (BM25 +
fuzzy) وليس فيه توسّع دلالي (مرادفات معنوية). إن كانت الدقة الدلالية مهمة لك،
أخبرني لأبني هذه الطبقة في جلسة منفصلة.

## سبب هندسي واجهته أثناء البناء (وحُلّ)
المحاولة الأولى لبناء BM25 (`07_build...`) بنيت كل شيء (سطحي+جذري) في تمريرة
واحدة ففشلت بـ`Killed` (نفاد ذاكرة) بسبب حجم المدونة الأكبر 5 مرات. الحل:
إعادة الهيكلة لمرحلتين منفصلتين مع `gc.collect()` بينهما، و`sys.intern()` على
الرموز المتكررة لتقليل استهلاك الذاكرة الفعلي — هذا موثّق في تعليقات
`07b_build_bm25_and_stems_adab.py` نفسه.

## الملفات
| الملف | الوظيفة |
|---|---|
| `01_build_passages_adab.py` | يبني جدولي `passages`/`passages_fts` داخل نسختك من قاعدة البيانات (يُشغَّل مرة واحدة على قاعدتك المحلية) |
| `07b_build_bm25_and_stems_adab.py` | يبني فهارس BM25 (سطحي وجذري) — يتطلب أن تكون `passages` موجودة مسبقاً |
| `08_hybrid_search_adab.py` | محرك البحث — `python3 08_hybrid_search_adab.py "استعلامك"` |
| `bm25_surface_adab.pkl.part_00..05` | فهرس BM25 السطحي، **مقسّم لـ6 أجزاء** (25MB لكل جزء) |
| `bm25_stem_adab.pkl.part_00..04` | فهرس BM25 الجذري، **مقسّم لـ5 أجزاء** |
| `bm25_passage_ids_adab.pkl`, `vocab_surface_adab.pkl`, `root_to_words_adab.pkl` | جاهزة، لا تجميع مطلوب |

### إعادة التجميع
```bash
cat bm25_surface_adab.pkl.part_* > bm25_surface_adab.pkl
cat bm25_stem_adab.pkl.part_* > bm25_stem_adab.pkl
```

## التشغيل
1. ضع كل هذه الملفات في نفس مجلد `فهرس_الادب_part1_sqlite3` الأصلي
2. شغّل `01_build_passages_adab.py` أولاً إن لم يكن جدول `passages` موجوداً في نسختك (الفهارس المرفقة هنا مبنية على تفكيك تم توليده محلياً وتُطابق هذا الترتيب فقط إذا شغّلت نفس السكربت)
3. جمّع أجزاء BM25 كما في الأعلى
4. `pip install rapidfuzz rank_bm25 nltk --break-system-packages`
5. `python3 08_hybrid_search_adab.py "استعلامك هنا"`
